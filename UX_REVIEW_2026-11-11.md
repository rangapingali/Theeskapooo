# Student ordering and paper preview update

Implemented a local, interactive A4 paper preview for the selected PDF or PNG in step 2. It supports 360-degree rotation, tilt, front/back inspection, individual sheet navigation, orientation, selected page ranges, copies, collation, one/two/four-up layout and simulated monochrome. The sheet planner is checked against the server's prepared-PDF ordering and blank-back insertion. Trending documents are not previewed by this component.

The preview uses Mozilla PDF.js, loaded only when a PDF needs rendering, with same-origin worker/font resources. It keeps only one source document and renders one sheet at a time with bounded canvas resolution. Documents are not uploaded for preview. Updates are debounced, stale render results are discarded, and preview failures do not block checkout. Clearing the selection releases preview resources.

Improved mobile field layout, button focus feedback, navigation clearance and shortcuts between settings and preview. Added recovery for unexpected background reconnect failures and guarded page counting against late work after timeout.

## Limits and deployment

This is a layout preview, not an exact printer proof. Device colour, paper handling and margins vary. PDF forms/annotations may differ from prepared-print support, so the original remains available. No physical phone/printer or authenticated production transaction was tested in this review. Preview content is not persisted across reloads. Hosting uptime, network failures and backend capacity still affect reliability.

Changes are local; deployment is not verified. Deployment must install the updated package lock and serve the new preview script plus PDF.js worker, fonts and CMaps. Existing Android-helper diagnostic edits were left untouched.
